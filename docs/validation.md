## Issues found and fixed during this run

First-admin advisory lock returned PostgreSQL void unsupported by Prisma query deserialization; switched to executeRaw. Document visibility originally lacked a captured resident audience; immutable membership snapshots plus live grants prevent later-occupant inheritance. Integration fixtures initially shared revoked state; now use isolated test members. Dynamic filesystem tracing was scoped/excluded so runtime mounts are not bundled. Multipart parsing now bounds actual streamed bytes and rejects duplicate/unknown fields. Worker gets a DB/Redis heartbeat healthcheck. Windows reserved port80; local rehearsal uses loopback8088/8443 while public Ubuntu remains80/443.

ClamAV1.4.3 initially reported March signatures; application correctly returned503. Freshclam download succeeded but old process had not loaded them. Upgraded maintained pinned1.4.6 and reloaded; actual VERSION reported 7October2026, real scan completed. The earlier stale-signature run used an explicitly host-inserted synthetic clean fixture solely for download/backup persistence; it was not counted as a successful malware scan. Subsequent actual upload/scan test passed.

## Reproduce disposable production acceptance

Use the deployment runbook to bootstrap a fictional `Rehearsal Society` and `bootstrap@example.test` with the synthetic test credential in tests/production/stack.spec.ts, only in a disposable stack. Use `.local/compose.env` with loopback8088/8443 and paths under .local. Set RUN_SYNTHETIC_REHEARSAL=true and run `npx playwright test --config playwright.production.config.ts --grep 'compiled HTTPS'`. MFA fixture secrets are kept in ignored .local; browser traces are disabled so recovery secrets are not captured. Never point this suite at a live society.

After backup.sh, restore to a distinct `*restore*` project on8444 with its own DATA_ROOT; set CHECK_RESTORED_STACK=true and run the `fresh-stack` test separately before rerunning the source test (which creates new fixtures). Keep synthetic decryption identity separate from backup directory; real deployments require off-VM identity escrow. Do not treat a checksum/script/runbook alone as recovery evidence.

RESTORED_URL can point the restore test to another loopback port (final run8445). The `host operator` test provisions a new fictional admin via stdin, enrolls MFA and exercises audited recovery. Every source acceptance run refreshes disposable recovery codes, creates new synthetic registry/file rows and restarts services; it is intentionally guarded by RUN_SYNTHETIC_REHEARSAL.
