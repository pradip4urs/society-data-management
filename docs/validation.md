## Failed attempts and limits

Initial checks caught a seed syntax error, conditional Prisma projection typing, MFA response-union typing, and a script module/narrowing error; corrected before final passing checks. Better Auth's build-time schema check identified current TOTP verified/failure/lockout fields; migration 003 fixed it. Browser test bursts initially hit the default authentication limit and ambiguous nested form-label selection. Authentication now uses atomic Redis storage with bounded login limits; explicit label IDs fix the accessibility/selection issue. Twelve browser tests then passed, followed by the full 13-passing suite including MFA.

Docker command failed because Docker is unavailable. Compose has not been started or runtime-tested. PostgreSQL used embedded real server binaries; Redis used Ubuntu/WSL binaries extracted into ignored .local paths, with no system package installation. Final S3 tests used SeaweedFS's official native Windows release. Initial MinIO image queries returned 401; replaced with available pinned SeaweedFS and documented the decision.

`npx tsx scripts/restore-drill.ts` did not complete: native embedded PostgreSQL lacks pg_dump/pg_restore client binaries. The script now requires an explicit PG_TOOLS_DIR and checks tool availability before creating a target. An empty synthetic society_restore_drill DB from the failed attempt remains for inspection. No successful restore drill, PITR or production recoverability is claimed. Backup/restore runbooks are provided for a Docker/client-tool-enabled host.

No independent penetration test, full WCAG audit, Firefox/Safari run, production HTTPS cookie check, infrastructure container startup, email delivery, malware scanning pipeline or financial acceptance tests were completed. All finance/gateway/report/export/document tests remain assigned to their future stages. UI has bounded first-page admin selectors and parking results; full scalability/filter-drawer work is outstanding.
